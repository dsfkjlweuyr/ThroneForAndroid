## Purpose

定义 T4A 自动选择器从候选规划、运行配置、健康决策到 Android 状态与控制的完整行为，使大规模订阅组能够稳定地自动选优、故障转移和恢复，同时让每次选择均可观察、可解释、可人工干预。

## ADDED Requirements

### Requirement: 自动选择器具有独立且持久的分组策略

应用 MUST 允许用户为一个普通或订阅分组选择自动选择器策略，并 MUST 持久化其候选过滤、排名上限、构建上限、测试结果可信窗口、健康检查、切换、连接重试、固定偏好与负载均衡配置。默认值 MUST 可直接工作；自动策略 MUST 默认关闭。

#### Scenario: 用户启用自动选择器

- **GIVEN** 一个包含多个节点的分组当前使用普通单节点或手动 selector 策略
- **WHEN** 用户选择自动选择器并保存
- **THEN** 应用持久化可判别的自动策略及其参数
- **AND** 未显式修改的高级参数采用可运行默认值
- **AND** 其他分组的策略不受影响

### Requirement: 候选集在构建时从被跟踪分组解析

自动选择器 MUST 在每次构建时从所属分组的当前成员解析候选节点，使订阅新增节点无需重新编辑策略即可加入候选。应用 MUST 支持不区分大小写的名称正则过滤和按逗号分隔的国家代码过滤；MUST 排除自动选择器、链式配置、无法作为同一运行配置成员的完整配置及无法成功构建的成员。过滤后无可用候选时 MUST 阻止启动并给出可诊断原因。

#### Scenario: 订阅加入符合过滤条件的新节点

- **GIVEN** 自动选择器按名称或国家过滤一个订阅分组
- **AND** 订阅更新加入一个符合条件的新节点
- **WHEN** 下一次规划候选集
- **THEN** 新节点自动出现在候选集中
- **AND** 用户无需编辑自动选择器设置

#### Scenario: 候选全部被排除

- **GIVEN** 分组成员均不符合过滤条件或无法作为自动选择器成员构建
- **WHEN** 用户尝试启动该分组
- **THEN** 应用拒绝生成空的自动选择器
- **AND** UI 或日志说明没有可用成员及主要排除原因

### Requirement: 候选排名复用有时效的 URL 测试结果

应用 MUST 将可信窗口内的成功 URL 测试结果按延迟从低到高参与排名，并 MUST 将未测试成员排在已测成功成员之后、已知失败成员之前。超过可信窗口的结果 MUST 被视为未测试；可信窗口为零时 MUST 总是重新测试。启用“跳过失败节点”时，仅可信窗口内的失败结果 MUST 将成员排除。只有候选数量超过运行构建上限且现有结果不足以确定入选成员时，启动前才 MUST 测量尚未测试或被明确标记为陈旧的候选。

#### Scenario: 启动前复用刚完成的分组测速

- **GIVEN** 用户刚对分组执行 URL 测试且结果仍在可信窗口内
- **WHEN** 启动自动选择器
- **THEN** 应用直接使用成功结果排名候选
- **AND** 不对具有新鲜结果的节点重复测速

#### Scenario: 旧失败结果过期

- **GIVEN** 一个节点上次测试失败但结果已超过可信窗口
- **WHEN** 重新规划自动选择器
- **THEN** 该节点被视为未测试而不是永久排除
- **AND** 在需要决定构建成员时可被重新测量

### Requirement: 运行配置限制成员规模并保留后备排名

应用 MUST 将排名列表限制在可配置的池上限内，并 MUST 只将排名最前的构建上限个成员及其完整代理链装入运行配置。池上限 MUST 不小于构建上限。成员顺序 MUST 作为内核冷启动时的排名先验；测速与导出单个节点 MUST NOT 扩展为整个自动选择器配置。

#### Scenario: 大订阅组启动

- **GIVEN** 一个分组有 1000 个合格节点且构建上限为 300
- **WHEN** 自动选择器完成排名并生成正式连接配置
- **THEN** 运行配置最多包含排名最前的 300 个成员
- **AND** 排名池仍保留未入选的后备成员供后续重建
- **AND** 单节点测速配置不包含其余成员

### Requirement: 内核按分层频率持续测量健康状态

运行中的自动选择器 MUST 高频检查当前活跃层，MUST 将其余运行成员均匀分布在较慢的全量轮询周期内，并 MUST 以独立的短周期监测当前承载流量的成员。健康排名 MUST 使用近期采样的平均延迟、抖动、成功与失败信息，MUST 允许配置采样数量、目标就绪成员数、活跃层大小、最大 RTT 和测试端点，并 MUST 避免大成员集在同一时刻产生探测突发。

#### Scenario: 当前成员停止转发但仍接受连接

- **GIVEN** 当前成员仍接受 TCP 连接但无法完成测试请求
- **WHEN** 当前成员专用监测周期到达
- **THEN** 自动选择器把该失败计入健康状态
- **AND** 立即提前触发活跃层检查而不是等待完整轮询周期

### Requirement: 自动决策具有迟滞、故障转移与拨号重试

自动选择器 MUST 优先使用符合健康阈值且排名最佳的成员。仅当挑战者比当前成员至少快于配置的切换容差，或当前成员失败/超过最大 RTT 时，自动决策才 MUST 切换。一次新拨号在所选成员失败时 MUST 按配置上限尝试其他可用成员；达到上限后 MUST 返回原始可诊断错误。策略切换时 MUST 按配置决定是否中断既有连接。

#### Scenario: 两个健康节点延迟接近

- **GIVEN** 当前成员延迟 100 ms、挑战者延迟 80 ms且切换容差为 50 ms
- **WHEN** 自动选择器重新排名
- **THEN** 当前成员保持不变
- **AND** 不因微小波动反复切换

#### Scenario: 当前成员拨号失败

- **GIVEN** 当前成员发生拨号失败且存在已确认可用的后备成员
- **WHEN** 新连接被创建
- **THEN** 自动选择器在同一次拨号中尝试后备成员
- **AND** 成功时实际选择与健康状态被同步更新

### Requirement: 本地断网不污染远端节点健康

自动选择器 MUST 使用 Android 网络状态以及可选的无代理连通性测试区分本地断网与远端节点集体失败。当判定本地网络不可用时，MUST 暂停健康惩罚、保留当前池与选择，并 MUST 在网络恢复后恢复探测；MUST NOT 因本地断网触发后备池重建。

#### Scenario: 设备进入飞行模式

- **GIVEN** 自动选择器正常运行且已有健康排名
- **WHEN** 设备失去所有可用网络
- **THEN** 自动选择器进入暂停状态并保留已有池
- **AND** 失败探测不把全部成员标记为远端故障
- **AND** 网络恢复后重新检查成员

### Requirement: 用户固定选择是可恢复的偏好而非不可用锁定

用户 MUST 能从运行状态中固定一个成员或恢复全自动。固定偏好 MUST 跨服务重启持久化；当固定成员健康时 MUST 优先使用它，当其不可用时 MUST 自动回退到其他健康成员，并 MUST 在固定成员恢复后回到该成员。固定目标不在当前构建成员中时 MUST 被安全忽略或在下次规划时清理。

#### Scenario: 固定成员暂时失效后恢复

- **GIVEN** 用户固定成员 A 且另有健康成员 B
- **WHEN** A 失效
- **THEN** 自动选择器临时切换到 B
- **AND** 状态说明用户偏好当前不可用
- **WHEN** A 后续恢复健康
- **THEN** 自动选择器重新选择 A

### Requirement: 负载均衡是显式可选策略

自动选择器 MUST 默认由单一成员承载流量，并 MAY 在用户显式启用后在确认健康的成员集内均衡。轮换模式 MUST 按配置周期切换整体选择并保持周期内会话亲和；按连接模式 MUST 为新拨号选择健康成员。均衡轮换 MUST NOT 以中断既有连接作为常规行为，且 UI MUST 说明按连接模式的出口一致性与流量归属限制。

#### Scenario: 启用轮换均衡

- **GIVEN** 至少两个成员已确认健康且用户启用轮换模式
- **WHEN** 轮换周期到达
- **THEN** 新连接转到下一个健康成员
- **AND** 既有连接不因常规轮换被主动中断

### Requirement: 运行状态与控制对 Android 可观察

应用 MUST 展示自动选择器的启动、探测、暂停、无可用成员与正常运行状态，并 MUST 显示当前成员、固定偏好、健康/总成员数、最近切换原因以及每个成员的延迟、抖动、采样和失败状态。用户 MUST 能触发立即复检、固定成员及恢复全自动；不存在运行实例、目标成员不存在或内核不可达时 MUST 返回明确失败而不是静默成功。

#### Scenario: 用户查看并复检运行组

- **GIVEN** 自动选择器正在运行
- **WHEN** 用户打开自动选择器状态页并点击立即复检
- **THEN** 页面显示当前状态与成员明细
- **AND** 内核启动一次不与正在进行轮询重叠的检查
- **AND** 后续状态刷新反映最新结果

### Requirement: 实际选择同步通知与流量归属

自动选择器的实际成员变化 MUST 同步到 Android 服务通知、Binder 客户端状态与流量统计。一个自动选择器包含的多个成员 MAY 共享该分组的总流量归属，但同一统计周期 MUST 去重，且按连接均衡无法精确归属时 MUST 明确采用近似语义。后台轮询状态 MUST 是幂等读取，不得清空内核计数或影响其他消费者。

#### Scenario: 内核自动故障转移

- **GIVEN** 自动选择器从成员 A 自动切换到成员 B
- **WHEN** Android 收到状态或选择变化通知
- **THEN** 服务通知显示 B 为当前成员
- **AND** 客户端状态刷新
- **AND** 自动选择器与成员流量不会因重复映射而被同一批次重复累加

### Requirement: 订阅变化和池耗尽触发受控重建

订阅更新删除、替换或改变当前构建成员时，应用 MUST 重新规划并重建正在运行的自动选择器。若全部运行成员持续不可用且设备本地网络正常，应用 MUST 从排名池中排除或降级本次失效成员，测量必要候选，并以接下来的最佳成员重建。无后备成员时 MUST 保持可诊断的耗尽状态并避免无限快速重启。

#### Scenario: 订阅替换正在运行的成员

- **GIVEN** 自动选择器的当前运行配置包含节点 A
- **WHEN** 订阅更新以不同配置替换或删除 A
- **THEN** 应用判定运行快照过期
- **AND** 重新规划候选并完整重建运行实例

#### Scenario: 所有运行成员失效

- **GIVEN** 本地网络正常且构建的所有成员持续失败
- **WHEN** 耗尽状态超过保护窗口
- **THEN** 应用从后备排名中选择下一批成员重建
- **AND** 重建受到防抖限制而不会形成紧密重启循环
